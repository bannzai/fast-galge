# 方向性: fast-galge

## 仮説

ノベルゲーム・ギャルゲーの定番の演出を知っている人は、文字送りが止められないほど速く、選択肢に 2 秒の制限時間があるギャルゲーを「変なゲーム」として笑い、遊んだ結果 (エンディング名と所要時間) を SNS で共有する。速さ以外 (立ち絵・背景・好感度・分岐・複数エンディング・バックログ・セーブ) を普通のギャルゲーの水準で揃えることで、「速いだけのネタ」ではなく「ちゃんとしたギャルゲーが速い」というずれが面白さになり、Steam と App Store で配信した作品として bannzai のアカウントの力になる。

## 判定基準

公開前は関門 3 (触れる版) で bannzai 本人が「速い会話が面白いか、それ以外はちゃんとギャルゲーか、人に見せたくなるか」を判断する。公開後は 14 日ごとに下の表で判定する。計測元は castle の skill で読める公開データに限る (ゲームに計測 SDK を入れない。関門 1 の返答「外部サービスとの新規連携: なし」)。SNS での反応は仮説の中心だが skill で読める計測元が無いため、判定基準の行にせず、判定日に bannzai が所感を「決めたこと」に書く。

| 指標 | 計測元 (skill / コマンド) | 継続のしきい値 | 打ち切り条件 | 転換の条件 |
| --- | --- | --- | --- | --- |
| Steam のレビュー数の 14 日間の増分 (`total_reviews` の差) | steam-market-research skill の `bash ~/.agents/skills/steam-market-research/scripts/fetch-app-details.sh fetch <appid> --cc JP --lang japanese` | >= 3 | 2 回連続で 0 | 増分はあるが好評率 (`positive_ratio`) が 70% 未満なら、否定レビュー (`fetch-reviews.sh fetch <appid> --type negative`) の不満 (速すぎる・短すぎる等) に沿って速度か分量を転換 |
| Steam の同時接続数 (`current_players`) の判定日の値 | 同上 | >= 1 | 2 回連続で 0 | — |
| App Store のレビュー数の 14 日間の増分 (`userRatingCount` の差) | appstore-research skill の `fetch-app-metadata.sh` (iTunes Lookup API) | >= 3 | 2 回連続で 0 | 評価 (`averageUserRating`) が 3.5 未満なら、レビューの不満に沿って転換 |

## 必要な機能

関門 1 (構想) で bannzai が確認した一覧 (2026-10-07)。配信先は Steam (Windows / macOS / Linux) と iOS。Android は計測手段ができてから足す。

- [ ] 高速会話: 文字送りが自動で進み止められない (1 メッセージ 0.4〜0.8 秒。文字数で変える)。選択肢は制限時間 2 秒で、時間切れは「……」(無言) を選んだ扱いになり好感度が下がる。操作はキーボードとタップ (選択肢・バックログのボタン) の両方
- [ ] シナリオと分岐: ヒロイン 2 人、各ルート 5 分前後。好感度で good / bad の 2 エンディングずつと、共通の bad エンディング 1 つ。シナリオは agent が書く
- [ ] ギャルゲーの基本演出: 背景・立ち絵 (表情差分)・名前つきメッセージウィンドウ・BGM と効果音・場面転換
- [ ] バックログ: 流れた会話をいつでも読み返せる (速さの救済。開いている間は会話が止まる)
- [ ] セーブ・ロード: 章の区切りでのオートセーブと、タイトルからの「つづきから」。端末内のローカル保存 (`user://`)
- [ ] エンディング一覧と周回: 見たエンディングの一覧、クリア後に「ゆっくりモード」(通常の速さ) を解放
- [ ] 共有できる結果画面: エンディング名・所要時間・選んだ選択肢の数・時間切れの回数を 1 枚の画像にし、X への共有 (端末の共有シートか、文面と画像の保存) ができる
- [ ] タイトル・設定・クレジット: 音量、素材のクレジット、利用規約・プライバシーポリシー・サポートページ (紹介ページのサポート節) とメールの宛先へのリンク (App Store の審査が求めるアプリ内の連絡手段)
- [ ] 配信: Steam 向けのデスクトップ 3 プラットフォームのエクスポート (CI の artifact) と Steam への提出 (Steamworks の登録の後)。iOS のエクスポートと TestFlight・App Store への提出 (Apple Developer Program は既存)
- [ ] 検証の仕組み: headless のロジック検証・入力統合テスト、CI での撮影と録画、Web エクスポート (検証専用。webtunnel で runner 上のブラウザから遊ぶ)。ローカル Mac で Godot を動かさない

入れていないもの: 課金・広告、アカウント、サーバー、計測 SDK、多言語 (日本語のみ)、ボイス、Android (計測手段ができるまで)、Web での配信。

## agent に任せること

- 画像生成の手段: game-art-reference skill の既定 (Codex の組み込み画像生成。Codex の利用枠を使い追加の課金なし) を使い、結果が合わない時だけ gemini-image-generator (約 $0.04/枚) を併用する
- 保存はローカル保存だけ。DB・認証・課金は持たない
- ビルド・テスト・画面の確認は GitHub Actions のランナーで行い、ローカル Mac で Godot を動かさない。Web ビルドの操作を伴う確認は webtunnel、iOS の simulator での確認は simtunnel (public リポジトリ)
- 利用規約・プライバシーポリシーは GitHub Pages のページ (App Store の Support URL と privacy URL にも使う)。課金が無いため特定商取引法に基づく表記は作らない
- 速度の具体値 (1 メッセージの表示時間・選択肢の制限時間) は実装しながら CI の録画で見て決める。値を変えた時は PROJECT.md と LP の記述も同じ変更で直す
- Steam のストアページ・App Store の製品ページの素材 (スクリーンショット・説明文・ヘッダー) は、関門 2 のデザインの反映の後に用意する
