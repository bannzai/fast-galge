# 0003. シナリオの保存形式を JSON (行の配列) にする

## Status

Accepted

## Context

会話エンジンの土台 ( https://github.com/bannzai/fast-galge/issues/3 ) で、会話文・話者・表情・選択肢・分岐先を置く保存形式を 1 つ決める必要がある (`.claude/rules/conversation-speed-and-scenario-single-source.md`)。候補は JSON と Godot の Resource (`.tres`) の 2 つ。

- シナリオは agent が書く (documents/PROJECT.md「登場人物とシナリオの規模」)。本編は 1 ルートで 400 メッセージを超える
- 開発マシンでは Godot を起動しない (AGENTS.md「検証方法」)。エディタで開かずに書けて、CI の headless の検証で誤りを見つけられる形式が要る
- 後続の issue がシナリオを足す (2 人目のルート、章の区切りのマーカー)。複数のセッションが同じ形式で書けることが要る

## Decision

- シナリオは **JSON** で `scenario/*.json` に置く。1 ファイルは行 (オブジェクト) の配列で、行はメッセージ・選択肢・ラベル・移動・エンディングのどれか 1 種類。行の種類とキーの定義は `scripts/scenario.gd` の冒頭のコメントを正とする (本 ADR には写さない)
- 複数のファイルは配列をつなげて 1 つのシナリオとして読む (本編は共通パート → ルート)。ラベルは全ファイルで共通の名前空間にする
- 移動先 (選択肢の分岐先・時間切れの分岐先・移動の行) は必ず後ろの行にする。前へ戻る移動を認めないことで、どの選び方でも会話がエンディングで終わることを形式で保証する
- 好感度はヒロインの ID ごとに持ち、選択肢は `{ヒロインの ID: 変化}` を持つ。時間切れで好感度が下がる相手は、その選択肢に名前があるヒロイン全員にする (下がる量は会話エンジンの定数で、シナリオには書かない)
- 表示時間・制限時間などの速さの値はシナリオに書かない (`scripts/conversation.gd` の定数だけに置く)
- 形式の誤り (知らないキー・無いラベル・前へ戻る移動・選択肢の数など) は `scripts/scenario.gd` の `validate` が見つけ、`make selfcheck` が `scenario/` の全ファイルに実行する
- Resource (`.tres`) は採らない。行ごとのサブリソースとスクリプトの参照 (`ext_resource`・`uid`) をエディタなしで手書きする必要があり、差分が読みにくく、書き間違いがロードの失敗としてしか現れないため
- JSON はスクリプトから `preload` されないデータのため、エクスポートの `include_filter` に `scenario/*.json` を入れる。エクスポート先を足す時は同じ指定を入れる (`make build-web` が pck に入っていることを確かめる)

## Consequences

- 良い点: テキストエディタと diff だけでシナリオを書ける。形式と所要時間を headless で検証できる。シナリオを足す issue はファイルを足して検証の対象に入れるだけで済む
- 悪い点: 行の型はエディタでは検査されず、検証は `validate` に書いた範囲に限られる。行の種類やキーを足す時は `scripts/scenario.gd` の定義と `validate` を同じ変更で更新する必要がある。前へ戻る移動 (同じ会話の繰り返し) は書けない
